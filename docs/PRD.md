# We-Scope — Product Requirements Document

> 제품명 **We-Scope**는 과정명 **We-Meet**과 "자세히 들여다본다"는 뜻의 **scope**를 합친 이름이다. 패키지·명령어 이름은 `wescope`이다.
> 이 문서는 **처음부터 다시 만드는 버전(v1)**의 요구사항이다. 기존 `WE_MEET` 코드(v0.2)는 참고·이식 대상이며, 이 문서가 기준이다.

## 1. 프로젝트 한 줄 정의

> We-Scope는 바이브코딩(AI 기반 코딩)으로 만든 웹 애플리케이션의 저장소를 **사용자 PC에서 분석**해, 보안 취약점 후보를 **OWASP 기준으로 분류**하고 **"무엇이, 왜 위험하고, 어떻게 고치는지"를 한국어로 설명**하는 로컬 대시보드형 보안 진단 도구이다.

### 핵심 철학

- **명령어는 하나, 화면은 대시보드** — 처음 한 번 설치한 뒤에는 터미널에 `wescope` 한 단어만 입력하면 내 PC에서 대시보드가 열린다. 연결·검사·결과 확인·보고서·설정은 전부 대시보드에서 한다. 별도 CLI 검사 명령은 없다.
- **정적 분석이 기준선, ChatGPT가 그 위를 덮는다** — 정적 분석은 누구에게나 같은 기준으로 기본 위험을 찾는다. ChatGPT(사용자 본인 구독)는 정적 분석이 놓치는 업무 로직·파일 간 흐름을 잡고, 의심 발견을 확인하고, **내 코드에 바로 적용할 수 있는 검증된 수정안**을 만든다.
- **수정안이 핵심 산출물이다** — 경고만 주지 않는다. 모든 위험에 수정 방법을 주고, ChatGPT를 연결하면 로컬에서 적용·문법·재검사까지 확인한 diff와 AI 코딩 도구용 수정 요청 프롬프트를 준다.
- **코드는 필요한 만큼만 PC를 떠난다** — 정적 분석은 전부 로컬. ChatGPT 분석을 켰을 때만, 비밀값을 자리표시로 바꾼 위험 코드와 관련 파일이 사용자 본인의 ChatGPT 계정으로 전송된다. 저장소 전체나 `.env`는 보내지 않는다.
- **바뀌면 다시 본다** — [다시 스캔]은 항상 지금 코드를 검사하고, 로컬 Git 폴더는 커밋할 때마다 자동으로 다시 검사한다. 새로 생긴 위험과 해결된 위험을 직전 검사와 비교해 보여 준다.
- **결과는 "후보"다** — 정적 분석 결과로 안전을 보증하지 않는다. 확인하지 못한 영역은 "검사 안 함"으로 정직하게 표시한다.

## 2. 문제 정의

ChatGPT·Claude·Cursor 같은 도구로 누구나 웹서비스를 빠르게 만들 수 있게 되었다. 그런데 AI가 만든 코드에는 다음 같은 실수가 자주 섞인다.

- 소스에 박힌 API 키, 커밋된 `.env`, `NEXT_PUBLIC_`으로 브라우저에 노출된 서버 키
- f-string으로 만든 SQL, `innerHTML`, `eval(req.body…)`
- 프론트에서만 숨기고 API는 열어 둔 관리자 기능, 남의 `id`로 조회되는 API
- `debug=True`, CORS `*`, `verify=False`, 쿠키 보안 속성 누락
- RLS를 켜지 않은 Supabase 테이블, 서명을 검증하지 않는 결제 웹훅, rate limit 없는 로그인·LLM 엔드포인트

기존 도구는 각각 한계가 있다.

| 기존 방식 | 한계 |
|---|---|
| Semgrep·Bandit·ESLint 같은 정적 분석기 | 경고가 영어 위주이고 난해하다. 초보자는 "그래서 뭘 고치라는 건지" 알기 어렵다 |
| gitleaks 같은 시크릿 스캐너 | 시크릿만 본다. 인가 누락·주입·설정 실수는 범위 밖이다 |
| AI에게 "내 코드 보안 점검해 줘" | 매번 결과가 다르고, 무엇을 검사했는지 알 수 없고, 코드를 짠 AI가 자기 맹점을 그대로 공유한다 |
| ARTEX 같은 자율 침투 도구 | 공격 관점의 블랙박스 1회성 진단이다. 소스를 보지 않고, 수정 가이드가 산출물이 아니다 |

We-Scope는 **결정론적 탐지(항상 같은 기준) + OWASP 분류 + 한국어 설명 + 커밋 추적 + 선택적 AI 분석**으로 이 간극을 메운다.

## 3. 타겟 사용자 페르소나

### Persona 1 — 바이브코더
AI 도구로 웹앱을 만들어 배포하려는 사람. 보안 용어가 익숙하지 않고 "동작하는지"에 집중한다. 위험도가 쉬운 말로 정리되고, 고칠 내용을 AI 도구에 그대로 붙여 넣을 수 있기를 원한다.

### Persona 2 — 학생·주니어 개발자
과제·공모전·포트폴리오 프로젝트를 GitHub에 공개하는 개발자. 공개 전에 기본 보안 점검을 하고, OWASP 같은 공식 기준으로 설명할 수 있는 결과를 원한다.

## 4. 핵심 기능 (우선순위 순)

### P1. 실행·저장소 연결·스캔 (모두 대시보드에서)

```bash
wescope        # 이것 하나뿐. 대시보드 서버를 띄우고 브라우저를 연다
```

| 순간 | 동작 |
|---|---|
| 처음 설치 | 한 번만: 저장소를 받아 설치하고 `wescope` 명령을 PATH에 등록 (PyPI 배포 후에는 `pipx install wescope` 한 줄) |
| `wescope` 입력 | `127.0.0.1`에 로컬 서버를 띄우고, 접속 티켓이 붙은 주소로 기본 브라우저를 연다. 터미널에는 주소와 "종료하려면 Ctrl+C"만 표시 |
| 이미 실행 중일 때 다시 입력 | 새 서버를 띄우지 않고 열려 있는 대시보드를 브라우저로 다시 연다 |
| 시작 화면 | 프로젝트가 없으면 **입력 칸 두 개**(프로젝트 폴더 경로 / GitHub 주소)만 있는 화면. 있으면 마지막으로 본 프로젝트의 최신 결과 |
| 검사 | 대시보드의 **[다시 스캔]**, 또는 로컬 Git 폴더에서 커밋할 때마다 자동 검사 |

입력은 두 가지뿐이다.

| 입력 | 검사 대상 | [다시 스캔] | 자동 검사 |
|---|---|---|---|
| **프로젝트 폴더 경로** (Git 저장소여도, 아니어도 됨) | 폴더의 **현재 파일**을 임시 폴더로 복사해 검사. 원본 폴더는 건드리지 않음 | 그 순간의 파일로 다시 검사 → 저장 안 한 변경까지 반영 | Git 저장소면 커밋할 때마다 (기본 켬) |
| **GitHub 주소** | `~/.wescope/repos/`에 clone한 뒤 기본 브랜치의 최신 커밋을 검사. 비공개 저장소는 사용자 PC의 git 로그인 정보 사용 | GitHub에서 최신 커밋을 받아 다시 검사 | 없음 |

폴더가 Git 저장소이면 파일마다 **커밋된 파일 / 아직 커밋 안 함 / `.gitignore`로 제외됨**을 함께 기록해 판정에 쓴다. 예를 들어 `.gitignore`에 들어 있어 커밋되지 않는 로컬 `.env`는 유출로 보지 않고, 커밋돼 있거나 커밋될 상태인 `.env`만 위험으로 본다. Git이 아닌 폴더의 `.env`는 "공유·배포할 때 포함되지 않게 확인하세요"(Potential)로 알린다.

자동 제외: `node_modules`, `.git`, `.venv`, `venv`, `build`, `dist`, `coverage`, `__pycache__`, `.next`, `.nuxt`, `.output`, `vendor`, `target`, `.gradle`, `.tox`, `.mypy_cache`, `.pytest_cache`, `*.min.js`, 5MB 초과 파일. 저장소의 `.wescopeignore`로 추가 제외할 수 있다.

### P2. 비밀값 노출 탐지 (WS-01)

| 하위 범주 | 탐지 대상 | 기본 심각도 |
|---|---|---|
| 환경변수 파일 | `.env`, `.env.local`, `.env.production` 등이 커밋됨(CRITICAL) 또는 `.gitignore`에 없어 커밋될 상태(HIGH). Git이 아닌 폴더는 MEDIUM | CRITICAL~MEDIUM |
| 코드 하드코딩 | `sk-`, `sk-ant-`, `AKIA`, `ghp_`, `glpat-`, `xoxb-`, JWT, `postgres://user:pass@` 같은 연결 문자열, `password`·`secret`·`api_key` 변수의 리터럴 값 | HIGH (AWS·service_role 등은 CRITICAL) |
| 프론트엔드 환경변수 | `NEXT_PUBLIC_`, `VITE_`, `REACT_APP_`, `NUXT_PUBLIC_`, `EXPO_PUBLIC_` + `SECRET`·`PASSWORD`·`PRIVATE`·`SERVICE_ROLE` (`ANON_KEY`·`PUBLISHABLE_KEY`·`PUBLIC_KEY` 제외) | HIGH |
| 클라이언트 번들의 고권한 키 | service_role 키·`sk-` 키가 `"use client"` 파일·`components/`·`public/`에 존재 | CRITICAL |
| 인증 파일 | `serviceAccountKey.json`, `credentials.json`, `*.pem`, `*.key`, `*.p12`, `*.jks`, `terraform.tfstate`, `terraform.tfvars` | CRITICAL |
| 인프라·CI 설정 | `docker-compose.yml`의 평문 비밀번호, `Dockerfile` `ENV` 키, `.github/workflows/*.yml`·`vercel.json`·`netlify.toml`의 하드코딩 | HIGH |
| 개발 도구 설정 | `.npmrc` authToken, `.pypirc`, `.netrc`, `.vscode/launch.json` 환경변수 | HIGH |
| 데이터·문서 | 커밋된 `*.sqlite`·`*.db`·`*.sql` 덤프·`*.log`, `.ipynb` 출력의 토큰, README의 `curl -H "Authorization: Bearer sk-…"` | MEDIUM~HIGH |
| Git 위생 | `.gitignore` 없음, `.env*`·키 파일 패턴 미등록 | MEDIUM |

모든 비밀값은 **앞 4글자만** 남기고 마스킹한다. 인증 파일·`.env`는 내용을 읽지 않고 경로와 종류만 기록한다. `your-api-key-here`, `process.env.X`, `os.environ[...]`, 테스트 픽스처 같은 자리표시 값은 오탐 필터로 제외한다.

### P3. 입력값 주입 탐지 (WS-05)

| 유형 | Python | JavaScript / TypeScript | 심각도 |
|---|---|---|---|
| SQL 인젝션 | f-string·`+`·`%`·`.format()`으로 만든 쿼리를 `execute` | 템플릿 리터럴·`+` 쿼리를 `query`·`raw` | HIGH |
| 코드 실행 | `eval()`, `exec()` + 외부 입력 | `eval()`, `new Function()` + 외부 입력 | HIGH |
| 명령 실행 | `subprocess(shell=True)`, `os.system()` + 외부 입력 | `child_process.exec()` + 외부 입력 | HIGH |
| XSS | `Markup()`, `|safe`, `render_template_string` + 입력 | `innerHTML`, `dangerouslySetInnerHTML`, `v-html`, `{@html}` | HIGH |
| 경로 조작 | 입력값으로 `open()`·`send_file()` 경로 구성 | 입력값으로 `fs.readFile`·`res.sendFile` 경로 구성 | HIGH |
| SSRF | 입력 URL로 `requests.get()` | 입력 URL로 `fetch()`·`axios` | HIGH |
| 역직렬화 | `pickle.loads()`, `yaml.load()` (안전 로더 미지정) | — | HIGH |
| 업로드 | `secure_filename()` 없이 파일명 사용 | multer 파일명 그대로 사용 | MEDIUM |
| 오픈 리다이렉트 | `redirect(request.args["next"])` | `window.location = 입력값`, `res.redirect(req.query.x)` | MEDIUM |

**외부 입력이 실제로 sink까지 흐를 때만** HIGH(Likely)로 본다. 입력 출처가 불분명한 패턴 일치는 Potential로 낮춘다.

### P4. 인증·인가와 위험한 기본값 (WS-02, WS-06)

|---|---|---|

| 쿠키 | Secure·HttpOnly·SameSite 누락 | MEDIUM |

| 기본 계정 | `admin`/`admin`, `admin`/`password` | HIGH |

### P5. 바이브코딩 특화 점검 (WS-03, 04, 07, 08, 09, 10)

| 영역 | 검사 | 심각도 |
|---|---|---|
| WS-03 데이터 계층 | Supabase 테이블 RLS 미활성화, `using (true)` 정책, `anon` 쓰기 권한 / Firebase `if true` 규칙 | CRITICAL~HIGH |
| WS-04 의존성 | `git+`·URL 의존성, 잠금 파일 없는 미고정 버전, `FROM python:latest` | MEDIUM |

| WS-08 남용 방지 | 로그인·회원가입·LLM 호출 라우트에 rate limit 없음, 업로드 크기 무제한 | MEDIUM |
| WS-09 LLM 연동 | 사용자 입력이 프롬프트에 결합, 모델 출력을 `eval`·SQL·HTML로 사용, 브라우저에서 LLM 키 사용 | HIGH~CRITICAL |
| WS-10 에이전트 설정 | `.claude/settings.json` 전체 허용, 버전 고정 안 된 MCP 서버, `CLAUDE.md`·`.cursorrules`의 지시 주입, 원격 스크립트 설치 훅 | MEDIUM~HIGH |

### P6. 변화 추적과 자동 검사

| 기능 | 내용 |
|---|---|
| 발견 지문 | `규칙 + 파일 + 정규화한 코드` 해시. 줄이 밀려도 같은 발견으로 본다 |
| 변화 상태 | 직전 검사와 비교해 **NEW / 그대로 / FIXED** 표시 |
| 커밋할 때마다 자동 검사 | 로컬 Git 폴더에 post-commit hook을 설치(기본 켬, 설정에서 끔). 커밋 직후 백그라운드로 검사하고 커밋을 느리게 하지 않는다 |
| 알림 없음 | 자동 검사가 끝나도 토스트·브라우저 알림·배너를 띄우지 않는다. 열려 있는 대시보드의 목록이 조용히 갱신되고, 닫혀 있으면 다음에 열 때 최신 결과가 보인다 |
| 이력 | 검사별 위험 점수·변화, 발견 이력 (로컬 SQLite) |

### P7. ChatGPT 분석 — 놓친 위험 찾기 + 수정안

**Sign in with ChatGPT**로 사용자 본인 구독을 쓴다 (API 키 없음, 서버 비용 없음). 상세 설계는 [AI.md](AI.md).

| 역할 | 내용 |
|---|---|
| **수정안 생성** (최우선) | 위험마다 내 코드에 바로 적용할 수 있는 diff, 파일별 변경 설명, 코드 밖에서 할 일(키 재발급 등), 확인 방법. 프로젝트의 프레임워크·ORM·관례를 맥락으로 함께 보낸다 |
| **수정안 검증** | 받은 diff를 로컬 임시 사본에 적용 → 문법 검사 → 같은 탐지기로 재검사해 문제가 사라졌는지·새 문제가 없는지 확인. 실패하면 이유를 붙여 한 번 더 고치게 한다. 화면에 **검증됨 / 문법 확인 / 검증 안 됨** 표시 |
| **보완 탐지** | 정적 분석이 원래 못 보는 곳(인가 로직, 결제·상태 전이, 대량 할당, 파일 간 흐름, 규칙이 없는 언어)을 골라 검토하고 새 위험을 추가. 실제 코드와 대조해 확인된 것만 남기고 `AI` 표시 |
| **의심 발견 확인** | "보호가 없어 보인다"(Potential)는 정적 발견을 미들웨어·호출부까지 읽고 확인 → `AI 확인` 또는 오탐 제안 |
| **설명 구체화** | 규칙의 일반 설명을 내 코드 기준 문장으로 |

| 항목 | 내용 |
|---|---|
| 분석 수준 | 끔 / 기본(수정안·확인·설명) / **심층**(기본 + 보완 탐지, ChatGPT 연결 시 기본값) |
| 보내는 것 | 위험이 있는 함수와 관련 정의, 보완 탐지 대상으로 고른 파일(인증·결제·인가 등), 프레임워크 정보. 비밀값은 자리표시로 바꿈 |
| 보내지 않는 것 | 저장소 전체, `.env`·키·인증 파일, 탐지된 비밀값 |
| 할 수 없는 것 | 정적 분석 발견 삭제·분류 변경, HIGH 이상을 사용자 확인 없이 오탐 처리, 사용자 코드 직접 수정 |
| 비용·일관성 | 코드가 안 바뀌면 이전 AI 결과를 캐시로 재사용, 스캔당 요청 상한, 사용량 초과 시 즉시 중단하고 정적 결과는 그대로 |
| 자동 검사 | 커밋 자동 검사에서는 "자동 검사에서 ChatGPT 사용"을 켠 경우에만 (기본 끔) |

## 5. 분류 기준

We-Scope는 두 가지 기준으로 발견을 분류한다.

| 기준 | 역할 | 쓰는 곳 |
|---|---|---|
| **We-Scope Top 10 (WS-01~10)** | 바이브코딩에서 실제로 자주 나는 실수 묶음. 사용자에게 보이는 기본 그룹 | 대시보드 홈, 보고서 목차 |
| **OWASP Top 10:2025 (A01~A10)** | 업계 표준 분류. CWE를 통해 자동 부여 | 발견 배지, 보고서 "OWASP 기준 점검 범위" 표 |
| OWASP Top 10 for LLM Applications 2025 / Agentic Applications 2026 | LLM·에이전트 영역 보조 분류 | WS-09, WS-10 발견 배지 |

| WS | 이름 | 대표 OWASP 2025 |
|---|---|---|
| WS-01 | 비밀값 노출 | A07, A01 |
| WS-02 | 인증·인가 누락 | A01, A04, A07 |
| WS-03 | 데이터 계층 공개 | A01 |
| WS-04 | 위험한 의존성 | A03, A08 |
| WS-05 | 입력값 주입 | A05, A01 |
| WS-06 | 위험한 기본값 | A02, A04, A07, A10 |
| WS-07 | 웹훅·결제 검증 누락 | A08, A06 |
| WS-08 | 남용 방지 부재 | A07 (+LLM10) |
| WS-09 | LLM 연동 취약 | A05 (+LLM01·02·05) |
| WS-10 | AI 에이전트 설정 오염 | A08 (+ASI01~05) |

규칙별 상세는 [RULES.md](RULES.md)를 따른다.

> OWASP Top 10은 인식 제고 문서이며 준수 체크리스트가 아니다. 보고서에는 "OWASP 준수·통과"라고 쓰지 않고 **"OWASP Top 10:2025 분류 기준 점검 범위"**라고만 쓴다.

## 6. 결과 출력

모든 결과는 **대시보드에서 보고, 대시보드에서 내려받는다.**

| 형식 | 용도 | 방법 |
|---|---|---|
| 로컬 대시보드 | 기본 사용 화면. 위험 목록·상세·검증된 수정안·검사 범위 | `wescope` |
| 한국어 보고서 (Markdown / HTML) | 공유·제출용 | 대시보드 [보고서 내려받기] |
| 결과 JSON | 원본 결과 보관·다른 도구에 넘기기 | 대시보드 [결과 JSON 내려받기] |
| 수정 요청 프롬프트 | AI 코딩 도구에 붙여 넣어 고치기 (검증된 diff 포함) | 상세의 [수정 요청 프롬프트 복사] |
| 수정 diff | 직접 적용하기 | 상세의 [diff 복사] |

CLI 옵션 대신 대시보드에서 조절한다.

| 하고 싶은 것 | 대시보드에서 |
|---|---|
| 특정 심각도만 보기 | 요약 줄의 심각도 숫자 누르기 (`HIGH 3` → HIGH만) · NEW / FIXED / AI는 보기 탭 |
| 특정 규칙 끄기 | 상세의 [오탐이에요] 또는 설정 창 > 이 프로젝트 > 꺼 둔 규칙 |
| ChatGPT 없이 검사 | 설정 창 > ChatGPT > 분석 수준 "끔" |
| 파일·폴더 제외 | 설정 창 > 이 프로젝트 > 제외할 파일·폴더 (폴더의 `.wescopeignore`도 읽음) |

화면 상세는 [DASHBOARD.md](DASHBOARD.md)를 따른다.

### 심각도

대시보드·보고서·프롬프트 모두 **영문 대문자 라벨**을 쓰고, 대시보드에서는 라벨 글자 색으로 구분한다 (색 값은 [DASHBOARD.md](DASHBOARD.md) §2).

| 라벨 | 기준 | 예시 |
|---|---|---|
| **CRITICAL** | 즉시 악용 가능, 데이터 전체·금전 피해로 직결 | service_role 키 클라이언트 노출, RLS 없는 공개 테이블, 커밋된 클라우드 인증 파일 |
| **HIGH** | 공격 경로가 명확한 취약점 | SQL 인젝션, 관리자 API 인가 누락, 하드코딩된 API 키 |
| **MEDIUM** | 조건이 맞으면 위험, 모범 사례 위반 | `debug=True`, CORS `*`, 쿠키 속성 누락, rate limit 없음 |
| **LOW** | 방어 수준 저하 | 예외 무시, 안전하지 않은 기본 설정 일부 |
| **INFO** | 참고 | 보안 관련 TODO, 정적 분석으로 확인할 수 없는 영역 안내 |

### 신뢰도

| 등급 | 의미 |
|---|---|
| Likely | 같은 함수 안에서 입력 → 위험 지점 흐름을 직접 확인했다 |
| Potential | 가드·설정이 **없는 것으로 보인다**는 추정이다. 상위 미들웨어 등은 확인하지 못했다 |

정적 분석 결과는 **Confirmed로 표시하지 않는다.**

## 7. 화면 구성 (로컬 대시보드)

열자마자 **위험 목록**이 보인다. 판정 문장·카드 없이 **왼쪽 목록 + 오른쪽 상세** 두 칸, 데스크톱 전용(최소 폭 1280px).

| 영역 | 역할 |
|---|---|
| **시작 화면** | 프로젝트가 없을 때: 입력 칸 두 개(프로젝트 폴더 경로 / GitHub 주소) + [검사 시작] + 전송 범위 안내 |
| **상단 바** | 로고 · 프로젝트 선택 · 상태 문장("마지막 검사 3분 전 · 커밋 a1b2c3d (자동)") · ChatGPT 연결 상태 · 설정 ⚙ · **[다시 스캔]** |
| **요약 줄** | `CRITICAL 1  HIGH 3  MEDIUM 4  LOW 1` 색 글자 · `NEW 2  FIXED 1` · 보조 위험 점수 · 보고서 내려받기 |
| **보기 탭** | 전체 · NEW · FIXED · AI · 오탐 표시 · 검사 범위 (심각도는 요약 줄 숫자를 눌러 거름) |
| **왼쪽 위험 목록** | 한 행 = 같은 규칙 묶음: 심각도 라벨(색) · 기술 이름("SQL 인젝션") · 위치 · `NEW`/`AI`/`AI 확인` 태그 · 수정안 상태 |
| **오른쪽 상세** | 탭: **수정안**(검증 상태·diff·코드 밖 할 일) · 설명 · 위치 · 판정 정보(WS·OWASP·CWE·신뢰도). 버튼: [수정 요청 프롬프트 복사] · [diff 복사] · [오탐이에요] |
| **검사 범위 탭** | WS 10개 · OWASP 10개 · ChatGPT 검토 범위 상태 표 |
| **진행 표시** | 검사 중 상태 문장 자리에 단계 표시(파일 수집 → 정적 분석 → 정리 → ChatGPT 분석 → 저장) |
| **설정 창** | 화면 가운데에 뜨는 창(폭 640px): 이 프로젝트 · ChatGPT · 화면 · 데이터 |

하지 않는 것: 판정 문장, 카드, 커밋 알림(토스트·브라우저 알림·배너), 단축키 기능, 전체 화면 설정. 상세 설계는 [DASHBOARD.md](DASHBOARD.md).

## 9. 보안·개인정보 설계

| 원칙 | 구현 |
|---|---|
| 읽기 전용 | 검사 대상 폴더를 수정하지 않는다. 현재 파일을 임시 폴더로 복사해 읽는다. 수정안도 diff로만 건네고 직접 적용하지 않는다 |
| 로컬 전용 서버 | 대시보드는 `127.0.0.1`에만 바인딩, 실행마다 발급하는 접속 티켓 필요 |
| 비밀값 마스킹 | JSON·SQLite·보고서·로그·AI 요청 어디에도 원문 비밀값을 남기지 않는다 |
| 민감 파일 미열람 | `.env`·키 파일은 경로와 종류만 기록한다 |
| ChatGPT 전송 범위 | 위험 코드·관련 정의·보완 탐지 대상 파일만, 비밀값은 자리표시로 바꿔 전송. `.env`·키 파일 제외. 커밋 자동 검사에서는 동의 전까지 미사용 |
| 토큰 보호 | ChatGPT 토큰은 사용자 PC에만 저장 (권한 600 또는 OS 키체인) |
| 코드는 데이터 | 스캔한 코드·문서 속 문장을 We-Scope나 AI에 대한 지시로 취급하지 않는다 |
| 허가된 대상만 | 본인 소유이거나 허가받은 저장소만 검사하도록 안내한다. 동적 공격 기능은 없다 |

README와 대시보드에 다음 문장을 표시한다.

> **정적 검사는 내 PC에서만 실행됩니다. ChatGPT를 연결하면 위험이 있는 코드와 관련 파일(비밀값은 가림)이 내 ChatGPT 계정으로 전송됩니다. 저장소 전체와 `.env`는 보내지 않습니다.**

## 10. 범위 밖 (Non-goals)

- 실행 중인 서비스에 대한 공격·침투 시뮬레이션
- 정적 분석 결과로 "안전" 판정
- 중앙 서버 호스팅, 회원 관리, 사용자 코드 수집
- OpenAI 외 LLM 구독 연동 (v1)
- 외부 스캐너 대량 연동 (Trivy·Checkov 등). 필요하면 "있으면 실행, 없으면 건너뜀"으로만
- **CLI 검사 명령·터미널 출력·종료 코드·CI 연동.** We-Scope는 대시보드 도구다. 터미널은 `wescope`로 대시보드를 여는 데만 쓴다
- 모바일·좁은 화면 레이아웃 (데스크톱 전용)
- 커밋 직후 알림(토스트·브라우저 알림·배너), 단축키 기능
- GitHub 주소 프로젝트의 자동 검사 (원격 변경 감지). GitHub 주소는 [다시 스캔]으로 최신 커밋을 검사한다
- 수정안 자동 적용·사용자 테스트 명령 실행 (수정안은 diff와 프롬프트로만 제공)

| **M1 엔진 + 첫 대시보드** | 엔진: WS-01·WS-05·WS-06 전체, WS-02 기본(Flask·FastAPI·Express), OWASP 자동 분류, 한국어 설명·기본 수정 예시. 대시보드: `wescope` 실행, 시작 화면(입력 2종), [다시 스캔], 위험 목록 + 상세, 수정 요청 프롬프트 복사, 보고서 내려받기, 설정 창 | `wescope` → 폴더 경로 입력 → 목록·상세 확인까지 터미널 입력 없이 완주. 취약 앱 기대 발견 재현, 안전 표본 오탐 0 |
| **M2 이력·자동 검사** | SQLite 이력, NEW/FIXED, 커밋할 때마다 자동 검사(알림 없이 화면 갱신), 오탐이에요, 프로젝트 여러 개 | 커밋하면 열려 있는 화면이 조용히 갱신됨 |
| **M3 ChatGPT 분석 + 바이브코딩 특화** | Sign in with ChatGPT, **수정안 생성·로컬 검증**, 의심 발견 확인, 보완 탐지, 입출력 가드, 캐시. WS-03·07·08·09, 체인 상관 | HIGH 이상 상위 그룹에 검증된 수정안, 벤치 앱의 업무 로직 취약점을 AI가 찾음 ([AI.md](AI.md) §10) |
| **M4 확장** | WS-04·WS-10, Next.js 라우트, Java(기존 구현 이식), HTML 보고서 | — |

**다음 멘토링 데모 목표: M1 + M3의 수정안 생성·검증**, 가능하면 M2 자동 검사. 수정안이 이 도구의 핵심 가치라서 M2보다 먼저 보여 준다.

### 함께 개발하기

친구들이 합류하면 트랙별로 나눠 병행한다. 트랙 사이 약속은 **결과 JSON 형식([ARCHITECTURE.md](ARCHITECTURE.md) §4)**과 **API([ARCHITECTURE.md](ARCHITECTURE.md) §7)**이다.

| 트랙 | 맡는 것 | 주요 폴더 |
|---|---|---|
| 엔진 | Collector, Analyzer, 정규화·비교·범위 | `collector/`, `analyzers/`, `engine/`, `rules/` |
| 대시보드 | 서버 API, 화면 | `server/`, `web/` |
| ChatGPT | 로그인, 수정안 생성·검증, 보완 탐지, 가드, 캐시 | `llm/` |
| 품질 | 테스트용 앱·벤치, 불변식 테스트 | `tests/`, `bench/` |

대시보드 트랙은 엔진이 완성되기 전에도 샘플 결과 JSON(`tests/fixtures/results/*.json`)으로 화면을 만들 수 있다.

## 12. 성공 지표

|---|---|

| 설명 완결성 | 모든 발견에 무엇·왜·어떻게 + 수정 예시 + OWASP(매핑 가능한 경우) |

| 비밀값 | 모든 출력 경로에서 원문 비밀값 0건 |

## 왜 만들었는가

AI 코딩 도구 덕분에 누구나 며칠 만에 웹서비스를 만든다. 그런데 AI가 만든 코드에는 **소스에 박힌 API 키, f-string SQL, 프론트에서만 막은 관리자 API, RLS 없는 Supabase 테이블** 같은 실수가 자주 섞인다.

기존 해결책은 각각 빈틈이 있었다.

| 방법 | 빈틈 |
|---|---|
| 정적 분석기 (Semgrep, Bandit, ESLint) | 결과가 난해하고 영어 위주. 초보자는 무엇을 고칠지 모름 |
| 시크릿 스캐너 (gitleaks 등) | 시크릿만 봄 |
| AI에게 "보안 점검해 줘" | 매번 결과가 다르고, 무엇을 검사했는지 모름. 코드를 짠 AI가 같은 맹점을 공유 |
| 자율 침투 도구 (ARTEX 등) | 공격 관점·블랙박스·1회성. 수정 가이드가 산출물이 아님 |

**We-Scope는 정적 분석으로 누구에게나 같은 기준선을 만들고, 사용자 본인의 ChatGPT 구독으로 정적 분석이 놓친 위험을 잡고 로컬에서 검증한 수정안을 만든다.** 결과는 OWASP 기준으로 분류하고 한국어로 설명한다.

## 아키텍처

```
터미널에 wescope → 대시보드 [다시 스캔] / git commit(hook)
        │
        ▼
  ┌─────────────┐
  │  Collector  │  현재 파일 스냅샷(GitHub는 최신 커밋), Git 상태, 민감 파일은 메타만
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │  Inventory  │  프레임워크·라우트·설정·SDK, 영역별 적용성
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │  Analyzers  │  10개 영역 플러그인, 실패 격리
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │  Engine     │  CWE→OWASP 분류, 지문, 체인, new/fixed 비교, 검사 범위, 점수
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │  ChatGPT    │  의심 발견 확인 · 보완 탐지(환각 방지 검증) ·
  │             │  수정안 생성 → 임시 사본에 적용·문법·재검사로 검증
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │  Dashboard  │  위험 목록 + 상세 · 검증된 diff · 수정 요청 프롬프트 · 보고서 내려받기
  └─────────────┘
```

### 설계 포인트
- **로컬 우선**: 정적 분석·저장·대시보드·수정안 검증 모두 사용자 PC에서. 외부로 나가는 건 ChatGPT 분석을 켰을 때의 위험 코드와 관련 파일뿐
- **기준선 + ChatGPT**: 정적 분석은 같은 기준의 기본 결과, ChatGPT는 그 위에 확인·새 발견·수정안을 덧붙임 (정적 결과를 지우거나 분류를 바꿀 수 없음)
- **검증된 수정안**: ChatGPT가 만든 diff를 임시 사본에 적용해 문법 검사와 탐지기 재실행으로 확인한 뒤 "검증됨" 표시
- **분류는 엔진이**: OWASP는 CWE에서 자동 계산, AI는 분류를 바꿀 수 없음
- **정직한 결과**: 검사하지 못한 영역을 "미발견"과 구분해 표시
- **결정성**: 같은 코드면 같은 결과 (ChatGPT 결과도 코드 해시 캐시) → 검사 간 비교가 의미를 가짐

## 핵심 기능 상세

### 1. 바이브코딩 특화 10개 영역
비밀값 노출 · 인증·인가 누락 · 데이터 계층 공개(Supabase RLS·Firebase rules) · 위험한 의존성 · 입력값 주입 · 위험한 기본값 · 웹훅·결제 검증 · 남용 방지 · LLM 연동 · AI 에이전트 설정까지, AI로 만든 앱에서 실제로 자주 나는 실수를 영역별로 묶었다.

### 2. OWASP Top 10:2025 자동 분류
각 규칙의 CWE를 OWASP 공식 카테고리별 CWE 목록과 대조해 `A05:2025 Injection` 같은 코드를 자동으로 붙인다. 보고서에 OWASP 10개 카테고리별 점검 범위를 표시한다.

### 3. 검증된 수정안 (핵심 기능)
We-Scope는 위험을 찾는 데서 끝나지 않고, **실제로 고쳐지는지 확인한 수정 방법**까지 건네준다.

1. **ChatGPT에게 충분한 정보를 준다.** 문제가 있는 함수 전체, 이 프로젝트가 쓰는 도구(Flask·Express, DB 라이브러리 등), 같은 문제가 있는 다른 위치까지 함께 보낸다. 그래야 프로젝트 스타일에 맞게 빠짐없이 고친 답이 나온다.
2. **ChatGPT가 고칠 내용을 만든다.** "이 줄을 지우고 이 줄을 넣어라" 형태의 변경 목록(diff)이다.
3. **We-Scope가 내 PC에서 시험해 본다.** 원본은 건드리지 않고 임시 복사본을 만들어, 고칠 내용을 실제로 넣어 보고 → 코드가 깨지지 않았는지 보고 → 다시 검사해서 문제가 사라졌는지 확인한다. 코드를 실행하지는 않고 읽어서만 확인한다. 시험이 끝나면 복사본은 지운다.
4. **실패하면 한 번 더 고치게 한다.** "이 줄이 안 맞아", "아직 위험하다고 나와"처럼 이유를 알려 주고 다시 요청한다.
5. **결과를 솔직하게 표시한다.** 화면에 **검증됨**(넣어 보고 다시 검사까지 통과) / **문법 확인**(코드는 안 깨졌지만 문제가 사라졌는지는 판단할 수 없음) / **검증 안 됨**(참고용) 중 하나로 보여 준다.
6. **바로 쓸 수 있게 넘겨준다.** [수정 요청 프롬프트 복사]를 누르면 문제 설명과 시험을 통과한 수정 내용이 함께 복사된다. Cursor나 Claude Code에 붙여 넣으면 바로 적용할 수 있다.
7. **코드로 끝나지 않는 일은 따로 알려 준다.** 코드에 박혀 있던 API 키처럼 이미 노출된 것은 코드만 고쳐서는 안 된다. "기존 키 폐기하고 새로 발급", "배포 서버에 새 키 등록" 같은 할 일을 체크리스트로 준다.

### 4. 정적 분석이 놓친 위험 찾기
인증·인가·결제·대량 할당·파일 간 흐름처럼 패턴이 없는 위험은 ChatGPT가 고른 파일을 검토해 찾는다. 응답의 인용 코드가 실제 코드와 다르면 버리고(환각 방지), 정해진 유형 목록에서만 골라 CWE·OWASP가 자동으로 붙는다. 정적 분석이 "보호가 없어 보인다"고 추정한 발견은 미들웨어·호출부까지 읽고 확인한다.

### 5. 변화 추적
`규칙 + 파일 + 정규화한 코드`로 지문을 만들어, 줄이 밀려도 같은 발견으로 인식한다. [다시 스캔]과 커밋할 때마다 자동 검사로 NEW·FIXED를 보여 준다. 알림으로 끼어들지 않고 화면만 조용히 갱신한다.

### 6. 안전한 ChatGPT 사용
`.env`·키 파일은 보내지 않고, 비밀값은 자리표시로 바꿔 보낸 뒤 로컬에서만 복원한다. 코드 속 지시문 같은 텍스트는 표시하고 그 파일의 오탐 제안은 무시한다. HIGH 이상을 오탐으로 넘기려면 사용자 확인이 필요하다.

## 트러블슈팅 / 설계 결정 기록

### 1. LLM 비용 → 로컬 우선 구조로 전환
- **문제**: API 키 방식은 토큰 비용을 개발자가 떠안는다.
- **결정**: Sign in with ChatGPT로 사용자 본인 구독을 쓰기로 함.
- **파급**: 약관상 요청이 사용자의 로컬 런타임에서 나와야 하고 토큰도 로컬에 저장해야 해서, 중앙 호스팅 서비스 구상을 버리고 **사용자 PC에서 도는 로컬 대시보드**로 구조를 바꿨다. 결과적으로 서버 비용 0, 코드가 PC를 떠나지 않음, 업로드 없이 커밋 감지라는 장점이 생겼다.

### 2. 커밋하지 않은 `.env`를 "유출"로 보고하는 문제
- **문제**: 작업 폴더를 그대로 읽으니, `.gitignore`로 잘 막아 둔 로컬 `.env`까지 "커밋된 비밀값"처럼 보였다.
- **v0.2 해결**: Git 저장소는 HEAD 커밋을 임시 폴더로 꺼내 검사했다. 그런데 이러면 커밋 전 변경이 반영되지 않아 "고쳤는데 다시 스캔해도 그대로"라는 문제가 생겼다.
- **v1 해결**: [다시 스캔]은 항상 **현재 파일**을 검사하고, 파일마다 Git 상태(커밋됨 / 커밋 안 함 / `.gitignore`로 제외됨)를 기록해 판정한다. ignore된 로컬 `.env`는 유출로 보지 않고, 커밋됐거나 커밋될 상태인 것만 위험으로 본다.

### 3. 줄 번호가 바뀌면 "새로 생김/해결됨"이 뒤집히는 문제
- **문제**: 위치 기반 비교는 위에 한 줄만 추가돼도 모든 발견이 바뀐 것처럼 보였다.
- **해결**: 줄 번호 대신 `규칙 + 파일 + 정규화한 코드` 해시를 지문으로 사용. 파싱에 실패한 파일의 발견은 "해결됨"이 아닌 "확인 불가"로 처리.

### 4. 자리표시 값 오탐
- **문제**: `your-api-key-here`, `process.env.KEY` 같은 값을 하드코딩 키로 판정했다.
- **해결**: 자리표시 값·환경변수 참조·테스트 파일 필터를 공통 모듈로 분리. 단, 서명 키에 쓰인 `secret`·`changeme`는 오히려 "약한 서명 키"로 잡도록 규칙을 나눴다.

### 5. 분류 기준을 KISA에서 OWASP로
- **문제**: 국내 가이드 기반 매핑을 시도했지만 원문 대조가 끝나지 않아 보고서 전면에 쓸 수 없었다.
- **결정**: KISA 매핑을 완전히 제거하고, 공식 CWE 목록이 공개된 **OWASP Top 10:2025**로 전환. CWE에서 자동 계산하므로 규칙과 분류가 어긋날 수 없게 했다.

### 6. 프로토타입이 꼬였을 때 — 문서 우선 재설계
- **문제**: 스프린트를 빠르게 쌓다 보니 탐지기마다 반환 형식이 다르고, 한 도구가 실패하면 전체 스캔이 멈추고, 분류 체계가 세 가지로 섞였다.
- **결정**: 기능 추가를 멈추고 PRD·아키텍처·규칙 카탈로그를 먼저 확정한 뒤 v1을 재작성. 기존 코드는 파일 단위로 "이식 / 고쳐서 이식 / 버림"을 정해 옮긴다.

### 7. AI가 결과를 조작당할 가능성
- **문제**: 스캔 대상 코드의 문자열이 AI 검토 모델에게 "이건 오탐"이라고 유도할 수 있다.
- **해결**: 지시문 의심 텍스트 표시와 그 파일의 오탐 제안 무시(입력 가드), 분류 변경 금지·심각도 하향 1단계 제한·HIGH 이상 오탐 확정은 사용자만(출력 가드), AI 발견은 인용 코드가 실제 코드와 일치할 때만 채택.

### 8. CLI를 버리고 대시보드 하나로
- **문제**:  CLI 검사 명령·옵션·콘솔 출력을 함께 두니, 바이브코더에게는 배울 것이 늘고 기능은 두 곳에 흩어졌다.
- **결정**: 사용자 명령은 `wescope` 한 단어(서버 시작 + 브라우저 열기)만 남기고, 검사·결과·보고서·설정을 전부 대시보드로 옮겼다. 커밋 자동 검사는 사용자 명령이 아닌 내부 모듈(`python -m wescope.hook`)이 처리한다. 대신 CI 연동은 범위에서 뺐다.

### 9. ChatGPT의 역할을 "설명"에서 "찾고 고치기"로
- **문제**: 처음에는 ChatGPT가 정적 분석 결과의 오탐 정리와 설명만 맡아서, "AI 없으면 뭐가 달라지냐"에 대한 답이 약했다.
- **결정**: ChatGPT에 정적 분석이 원래 못 보는 영역(업무 로직·파일 간 흐름)의 보완 탐지와, 이 도구의 핵심 산출물인 수정안 생성을 맡겼다. 대신 AI 결과를 그대로 믿지 않도록 **인용 코드 대조**(발견)와 **적용·문법·재검사**(수정안)로 로컬에서 검증하는 단계를 붙였다.

### 10. 화면을 "할 일 카드"에서 "목록 + 상세"로
- **문제**: 판정 문장과 카드 중심 화면은 한 번에 보이는 항목이 적고, 수정안 diff를 보여 줄 자리가 좁았다. 커밋 직후 알림도 작업 흐름을 끊었다.
- **결정**: 열자마자 위험 목록이 보이는 두 칸 구성으로 바꾸고, 심각도는 `CRITICAL`·`HIGH` 영문 라벨과 글자 색으로만 구분했다. 상세의 기본 탭을 수정안으로 두고, 알림·단축키·판정 문장은 뺐다. 입력도 폴더 경로와 GitHub 주소 두 가지로 줄였다.

### 11. 이름 중복 → We-Scope
- **문제**: 프로토타입 이름 VibeScan은 같은 이름의 Python CLI 도구 등 이미 여러 곳에서 쓰이고 있었다.
- **결정**: 과정명 **We-Meet**과 "자세히 들여다본다"는 **scope**를 합친 **We-Scope**로 변경. 패키지·명령어는 `wescope`, 분류 코드도 VS-01~10에서 **WS-01~10**으로 바꿨다. 결정 당시 PyPI·npm에 같은 이름 패키지가 없음을 확인했다.

## 배운 점

- **제약이 구조를 결정한다**: LLM 약관 하나가 호스팅 서비스 → 로컬 도구로 제품 형태를 바꿨다.
- **보안 도구일수록 "모른다"를 말해야 한다**: 검사하지 못한 영역을 숨기면 사용자는 안전하다고 오해한다.
- **AI는 맡기되 검증한다**: 놓친 위험 찾기와 수정안처럼 AI가 잘하는 일은 크게 맡기고, 결과는 실제 코드 대조·재검사로 로컬에서 확인한다. 분류와 기준선은 결정론적 엔진이 지킨다.
- **문서가 먼저다**: 기준 없이 쌓은 기능은 결국 다시 정리해야 했다.
